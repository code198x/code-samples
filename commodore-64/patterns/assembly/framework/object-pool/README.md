# Bounded object slots on C64

Include `cross-platform/patterns/framework/object-pool/6502.inc` once after defining POOL_FLAGS and POOL_CAPACITY. Caller owns capacity contiguous writable bytes; capacity must be 1..255. The maintained fixtures qualify 4 and 8, not all capacities. `pool_init` clears flags only. Acquire claims the first zero byte, returns C=0 and X=index; full returns C=1 and X=capacity without writing. Test carry before indexing payload arrays. Release takes X, returns C=0 when it clears an occupied slot; invalid or already-free returns C=1 without a write. A/flags change; init/acquire also X. Release preserves X. Y/decimal mode survive. No zero-page pointer, heap, hardware register or hidden state. Not re-entrant: give the pool one owner and defer interrupt requests.

Flags must be 0 or 1. Payload such as position, velocity and lifetime is separate. Initialise every required payload field after acquisition and before any reader sees that slot. Release changes flags only. Reused numbers are not durable handles: discard old references or design/verify generations separately. No automatic sprite allocation, compaction or full-pool eviction policy.

Optional `age6502.inc` scans fixed slots in ascending order, decrements life for each occupied slot and releases those reaching zero. Occupied slots require life 1..255. Zero would underflow to 255. It preserves Y, changes A/X/flags and uses another nested JSR on expiry. Apply spawns after the pass, otherwise a newly reused later slot can update on the same step. No payload or index moves on deletion.

Measured at this address layout: helper 47 code bytes, capacity flag bytes; optional age helper 19 code bytes and capacity lifetime bytes. Helper direct calls use two return-address stack bytes; ageing can add two more on release, plus enclosing calls/interrupts. Init writes N flags; acquire reads through the first free flag or all N when full; release checks one in-range flag and at most writes one. Age reads N flags, decrements each live lifetime and calls release per expiry. These operation counts are not hardware cycle measurements. Different address modes/page crossings change cost.

`demo.asm`: capacity8. `custom.asm`: capacity4 (same measured code size, four fewer flag and four fewer lifetime bytes). `wrong.asm`: deliberately omits the release before reacquiring slot1. `repaired.asm` restores it and is binary-identical to demo. Preview bytes: 00 01 02 FF 01 01 AA 00; wrong field5 is FF; custom field7 is 0A. Fields are first three indices, full-pool sentinel, reacquired index/sentinel, invalid-release carry, occupancy after one and two lifetime passes. FF is a caller's display sentinel, not a successful slot.

The standalone PRG enters through the stock PAL BASIC/KERNAL startup, disables IRQ sources, owns the screen at $0400, character RAM at $2000 and colour RAM, and does not return to BASIC. The component itself changes no video, bank or interrupt registers.

Fixture private scratch $70–$78, flags at $81 with guards immediately before/after, lifetimes at $90. It additionally owns the guarded output buffer and display. The full artifact is 686 bytes including native packaging and diagnostics; this is not the helper cost. The fixture's occupancy-byte renderer supports capacity1..8; do not increase it to the helper's theoretical255 limit without replacing the fixture and verifying bounds.

Build: `make ASM198X=/path/to/asm198x`. Native qualification: `python scripts/verify-object-pool.py --system commodore-64 --assembler /path/to/asm198x --emulator /path/to/emu198x-c64 --firmware /path/to/c64-rom-directory`. NES does not use firmware; that argument is unused there. Verification uses Asm198x0.0.72 and Emu198x0.44.2. Firmware hashes stay in configuration.json; no ROMs or firmware-bearing snapshots are distributed.

The second native caller checks all256 occupancy masks for each configured capacity (upper bits ignored in capacity4), allocate/invalid-release/free/double-free results, Y preservation, guards, cleared flags and every untouched lifetime payload byte. A set-based oracle checks the emitted records. The real startup path and loaded code, working/custom/broken/repaired pictures, safe ageing results and exact repair are retained. `python scripts/check-object-pool.py` and `python -m unittest discover -s scripts -p test_object_pool.py -v` require both targets and reject44 altered records plus2 mismatched-picture claims. This qualifies these named emulator workloads, not physical-hardware timing or a complete game.
