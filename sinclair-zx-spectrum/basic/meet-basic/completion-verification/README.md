# Meet BASIC completion checkpoints

Twenty complete learner listings continue the published opening and first Lucky Number lessons:

- Units 7–8 finish Lucky Number with random selection, colour, brief sounds and replay.
- Units 9–11 build Oracle Stone: selected replies, a counted rhythm and a shared heading routine.
- Units 12–15 build a marker experiment: position, drawing and erasing, polling, boundaries, release waiting and quitting.

Each `steps/step-NN.bas` is the whole runnable state. Paths under `lucky-number/`, `oracle/` and `movement/` are separate from the older reference samples. Load the named lesson's first state into an empty program, or follow its explicit numbered-line edits from the preceding state.

## Reproduce the checks

Requires Python 3, the released Emu198x Spectrum executable, and a lawfully supplied 48K ROM configured in Emu198x. The scripts reuse the opening's MCP transport and type BASIC through ROM key chords; they do not inject tokenised BASIC or patch machine memory.

```sh
python3 verify.py --emulator /path/to/emu198x-spectrum --output /tmp/meet-basic-completion
python3 experiments.py --emulator /path/to/emu198x-spectrum --output /tmp/meet-basic-experiments
python3 check_audio.py /tmp/meet-basic-completion
```

`verify.py` accepts `--arc lucky-number`, `--arc oracle`, `--arc movement` or `--unit 15` for focused reruns. It saves per-checkpoint progress, screenshots, three WAV recordings and named tapes for each finished program. The opening's helper starts a fresh MCP process for tape recovery checks.

Random play uses the actual random expression and guesses through the promised range. Fixed-secret and forced-answer edits are explicitly test-only; the original learner lines are restored before saving. The experiments cover a fixed seed, a finite bounded random sample, a changed divider at both calls, five loop visits, the legal print-area corners and sampled motion. The finite sample does not prove fairness.

The 6 September 2026 run used Emu198x v0.22.1 on Apple silicon, Spectrum 48K. `units-07-14-results.json` records the completed checks before a defect was found in the first unit-15 program: idle input could enter release waiting and discard a new press. Line 71 now returns empty input directly to polling. `unit-15-results.json` records the corrected program's focused rerun. `experiments.json` and `audio-checks.json` hold the additional evidence.

The audio check measures short sustained-note windows in these exact input sequences. It confirms the expected pitch order and a non-silent capture, not perceived loudness, sound quality or native host output. Listen to the generated WAVs and try native controls before publication. Motion evidence samples the emulated display over time; it is not an original-hardware or native-window observation.

All sound is generated by the learner programs. Screenshots for units 8–15 come from these runs; the unit-8 figure is explicitly a fixed-secret test, while the Oracle figures use the ordinary random selection path. The two intermediate motion figures are frame samples from `experiments.py`.
