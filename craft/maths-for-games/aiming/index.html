02 / WHAT THE PICTURE MEANS

One angle, two components

Start at (0, 0). Measure angles anticlockwise from the positive X axis. At 0°, all movement is right; at 90°, it is up. Past 90°, the horizontal component becomes negative.

The triangle on the range is enlarged to the target’s distance. Its legs are distance × cos(angle) and distance × sin(angle). Movement uses the same proportions, multiplied by speed instead.

Radians measure an angle as arc length divided by radius. One turn is 2π radians, so radians = degrees × π / 180. JavaScript’s trig functions take radians.

03 / KEEP THE FRACTION

Small errors travel

For each component, store round(velocity × scale). Add that integer to the stored position every tick. Divide by the scale when drawing. Fractions survive because position uses the same scale as velocity.

Try the calculated angle at scale 4, then repeat at scale 256. Does the fixed-point shot still miss? The two shots begin with the same angle; only their stored velocity differs.

The stored values fit signed 16-bit velocity and signed 32-bit position. We round halves away from zero. The range keeps both within bounds. The fractional reference uses JavaScript numbers; it is not infinite-precision arithmetic.

A mathematical experiment, not a native-machine benchmark. No gravity, drag or moving targets. Contact is checked along each movement segment, so a shot cannot jump over the target between ticks. Screen Y is inverted when drawing; world Y stays positive upwards.
