# Execute five FDC commands from a normal ROM-loaded program

The umbrella owns orchestration and results. This MIT fixture owns only readable
Z80 source. Reuse disk-plus3/loader.bas and Build198x's standard 180KiB disk.

1. Add fdc-commands.asm: seek track39, normal-write sector2, deleted-write sector1,
   verify deleted read-back, read two represented sectors, compare Equal/Low/High
   on sector2, retain each seven-byte result, draw screen and compute completion.
   Track39 is outside these small authored files; the runner verifies allocations.
2. Use direct guest port polling, with runner emulated-frame and host deadlines.
   No ROM interception, host port writes, memory injection or state restoration.
   Preserve original disk files; live writes remain in memory/exported new files.
3. Build with released Asm and independent Pasmo, compare every payload byte;
   master/load through normal ROM. The umbrella checks byte patterns, statuses,
   source immutability and live exported sector marks. Negative runs must reject.
4. Document bounded implementation expectations versus unresolved physical/status
   conformance, then push the independently reviewable fixture PR after checks.

## Wait for seek completion instead of assuming its duration

Stock MAME cold-ROM loading exposed a fixture bug before any data command:
the fixed loop allowed about120ms, then Sense Interrupt returned its valid
one-byte no-pending80 result while MSR81 still showed driveA seeking. The
fixture demanded a second result byte and entered its failure loop. This is
separate from MAME's known Scan disagreements.

Replace the fixed delay with runner-bounded polling of Sense Interrupt. Drain
one-byte no-pending80, or the existing Emu two-byte80,00 representation using
MSR CB/DIO. Drain other-drive completions; require normal seek-end for driveA
and PCN39. Reject errors, wrong target PCN and an excess result byte. Use a
short retry backoff without deriving or asserting a physical seek duration.
No loader bypass, host controller writes or runtime changes.

Verify Asm/Pasmo payload identity, fresh CI-artifact execution and fresh stock
MAME ROM loading. MAME must progress beyond setup; known Scan failure remains
failed independent evidence rather than fixture completion. Keep source image
immutable and private firmware directories automatically cleaned.

### Verified seek correction

Observation-only MAME0.289 port taps recorded Seek bytes0F,00,27 at
12.482535–12.482590 emulated seconds. The original fixture sent Sense08 at
12.602737; MSR81 still showed driveA seeking. Its single80 result was valid,
but the fixture demanded a second byte. With polling, MAME eventually returns
normal seek-end20 and PCN39 at12.927400/12.927452. No elapsed-time value is an
acceptance condition in the corrected fixture.

Asm0.0.66 and independent Pasmo produce identical4082-byte payloads. The fresh
CI-artifact preflight (Emu source47ec824ec30f0176467c99eb0b17cab98527e22a,
executable SHA25674bbbfa1b6d88716b5332d63669e7851497fc750c5812ca11eead36e7cccc2e4)
passes523 native assertions and776 guest/export assertions, phase5/error0,
computed90/91 completion and unchanged source disk. This is a CI artifact,
not a distributed release qualification.

Two fresh stockMAME cold-ROM loads pass seek, normal/deleted writes, deleted
readback and the represented two-sector Read Track check, then fail the known
ScanEqual status check: observed40,80,08,27,00,02,02 instead of a normal hit.
Both retain phase2/error1 and remain failed reference runs. This correction
therefore exposes the existing reference disagreement instead of hiding it
behind a setup failure. No host writes or snapshot inputs were used.
