# Tile maps beyond the launch machines

Parent: code198x/docs#117. Source base: 515cef62bb93fcd68b6f9703c445d8b2bc38c279.

Keep map storage/query code distinct from the display adapter. Reuse the existing stock BASIC loading paths, display observers and lesson map concepts. Do not promote an input/drawing probe into tilemap evidence.

1. Inventory all 30 registry machines in `docs/tilemaps/coverage.json` and `docs/tilemaps/README.md`, including existing lesson code and exact remaining gaps. Verify registry membership and every linked path.
2. Add reusable BASIC map routines and complete small callers to the ten existing non-core BASIC probe systems: Atom, CPC, Atari 800XL, PET, VIC-20, Dragon, Aquarius, MSX1, Oric and SVI-328. Files: `<system>/patterns/basic/rendering/tile-map/{routines.bas,demo.bas,README.md}`. Show row-major numeric storage, checked get/set, separate property lookup, pixel-to-cell conversion and bounded text-region drawing. Match each ROM's actual dialect; do not claim graphical tile drawing.
3. Verify each caller via its stock ROM and keyboard in Emu198x built from source 373c85ad2b76aa6ac765776f9840b4d6951b3aed. `scripts/verify-tilemaps.py` checks visible region/query results, rejected out-of-range writes, boundaries, tile-property independence and deliberate broken-index variants. Retain source/tool/firmware hashes and results under `docs/tilemaps/verification/`; restricted firmware remains local.
4. Publish a shared family entry plus machine implementation explanations through CodeFromFile. Use existing schema/routes where possible; any added platform enum values are additive and must have matching discovery metadata. Link original lesson/Vault material. Record further assembly, FORTH, ZX dialect and native graphical adapters as unfinished, not unsupported.
5. Run meaningful dialect/observer checks, website checks/build and desktop/phone discovery/content checks. Commit and push isolated work, create draft PRs, attach them and retain review outputs. No new dependencies or deployment without a later publication instruction.

The user confirmed the broad map/query-first design during implementation. Extend this same tranche to the other twenty systems using shared 6502/Z80/SM83/68000 includes and individually reserved contexts/callers. `cross-platform/patterns/rendering/tile-map/{6502.inc,z80.inc,sm83.inc,m68000.inc,native.json,build.py,README.md}` owns the CPU code and diagnostic packaging; each machine has `patterns/assembly/rendering/tile-map/{demo.asm,Makefile,README.md,verification/results.json}`. `scripts/verify-native-tilemaps.py` checks every machine independently with original synthetic ROMs/cartridges, 44 result bytes and completed wrong-stride and unsafe-write controls. Nineteen maps cross a page boundary; the 2600 stays within its RAM window. These are CPU/RAM qualifications, not stock-loader or graphics claims.

Native graphics remains separately qualified on every system; a BASIC text region is not a VDP, bitmap, MARIA or TIA renderer. Complete query coverage must not mark those other paths complete.
